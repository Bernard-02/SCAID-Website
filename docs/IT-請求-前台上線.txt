請求二：一組上傳用的存取金鑰（Access Key ID＋Secret Access Key）
════════════════════════════════════════════════

  用途：學程負責網站的人用它把網站檔案上傳到 S3、上傳後清 CloudFront 快取。
  不需要 Console 管理權限，最小權限即可：

    ・對該 bucket：列出、讀取、上傳、刪除物件
    ・對該 distribution：建立 invalidation（清快取）

  政策範例（僅供參考，以實際環境為準）：

    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Effect": "Allow",
          "Action": ["s3:ListBucket", "s3:GetBucketLocation"],
          "Resource": "arn:aws:s3:::<bucket 名稱>"
        },
        {
          "Effect": "Allow",
          "Action": ["s3:GetObject", "s3:PutObject", "s3:DeleteObject"],
          "Resource": "arn:aws:s3:::<bucket 名稱>/*"
        },
        {
          "Effect": "Allow",
          "Action": ["cloudfront:CreateInvalidation", "cloudfront:GetInvalidation", "cloudfront:ListInvalidations"],
          "Resource": "arn:aws:cloudfront::<帳號ID>:distribution/<distribution ID>"
        }
      ]
    }

請求三：CloudFront 設定（三項，與 sccd.usc.edu.tw 現行設定相同）
════════════════════════════════════════════════

  (1) Default root object
        index.html

  (2) Error pages：新增兩條 Custom Error Response

        HTTP Error Code : 403 → Response page path: /index.html → HTTP Response code: 200
        HTTP Error Code : 404 → Response page path: /index.html → HTTP Response code: 200
        Error caching minimum TTL：0（或 5 秒以內）

      ・原因：網站是單頁應用，scaid.usc.edu.tw/about 這種網址在 S3 裡沒有對應的檔案，
        需要 CloudFront 把找不到的路徑導回 /index.html，由前端程式顯示對應的頁面。
      ・⚠️ 403 那條一定要加，不能只加 404：
        私有 bucket 對「找不到的檔案」回的是 403 AccessDenied（不是 404）。
        只加 404 的話，內頁重新整理仍會出現 AccessDenied 的錯誤畫面。
      ・sccd.usc.edu.tw 目前就是這樣設的（實測 sccd.usc.edu.tw/about 回 200、X-Cache: Error from cloudfront）。

  (3) 快取標頭：Cache-Control: no-cache

      ・sccd.usc.edu.tw 的檔案回應帶有 Cache-Control: no-cache（實測），請讓 scaid 也一樣。
        若 SCCD 是在 CloudFront 設的（Response headers policy 或 Cache policy），請套用同一份；
        若 SCCD 不是在 CloudFront 設的，請回覆告知，學程會在上傳時自己加在檔案上。
      ・原因：網站的 CSS／JS 檔名不帶版本號，沒有這個標頭，訪客的瀏覽器會繼續用舊檔，
        網站更新後看不到新版。

  其餘設定（HTTP 轉 HTTPS、自動壓縮等）比照 sccd.usc.edu.tw 的 distribution 即可。
  三項設定完成、distribution 狀態為 Deployed 後，請建立一次 invalidation（paths：/*）。
